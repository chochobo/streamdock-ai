# macOS 네이티브 앱

이 앱은 SwiftUI 설정 창과 메뉴 막대를 사용합니다. 장치 연결은 Swift HID가 기본이며, 기능은 앱에 포함된 Node 백엔드가 실행합니다. 게임과 화면보호기는 이 Mac의 Python·Pillow를 사용합니다. 백엔드를 Swift로 모두 옮긴 상태는 아닙니다.

네이티브 앱의 기본 장치 드라이버는 Swift HID 브리지입니다. 2026년 11월 10일 실제 293S에서 화면, 물리 버튼과 USB 분리 후 재연결을 사용자가 확인했습니다. 이전 `node-hid` 경로가 필요하면 실행 중인 앱을 종료한 뒤 `open build/native/StreamDockAI.app --args --node-hid`로 실행하세요. 두 드라이버가 동시에 장치를 열지 않습니다.

## 빌드

이 Mac에서 Xcode의 Swift 컴파일러, Node 22 이상, Python 3와 Pillow가 필요합니다. 프로젝트의 `node_modules`에 현재 Mac에서 동작하는 `node-hid`와 `sharp`가 있어야 합니다. 네트워크 설치는 실행하지 않습니다.

```sh
./scripts/native-build.sh
open build/native/StreamDockAI.app
```

빌드는 Node 실행 파일, 백엔드와 네이티브 모듈을 앱에 복사합니다. 기존에 만든 앱이 있으면 삭제하지 않고 `build/native`에 이름을 바꿔 보관합니다. 이 Mac의 유효한 Apple Development 서명 신원이 하나일 때 자동으로 선택하며, 인증서 지문을 앱에 기록해 다음 빌드에서도 같은 신원을 사용합니다. 신원이 없거나 여러 개면 명시하지 않은 다른 인증서나 임시 서명으로 전환하지 않고 빌드를 중단합니다. 다른 Mac에 배포할 때 필요한 서명·공증이나 범용 아키텍처 지원은 별도로 확인해야 합니다.

기존 앱을 건드리지 않고 검토용으로 빌드하려면 `scripts/native-build.sh --stage-only`를 실행하세요. 서로 다른 신원을 선택해야 할 때는 `STREAMDOCK_SIGN_IDENTITY`에 유효한 인증서의 40자리 지문을 명시할 수 있습니다. 이 방법으로 키체인에 직접 만든 자체 서명 코드 서명 인증서도 사용할 수 있습니다. 이때 앱의 서명 요구조건은 그 인증서 하나에 고정되므로, 같은 인증서로 계속 빌드하면 macOS 권한이 유지됩니다. 자체 서명 인증서는 자동으로 선택하지 않습니다.

```sh
security find-identity -v -p codesigning   # 40자리 지문 확인
STREAMDOCK_SIGN_IDENTITY=<지문> ./scripts/native-build.sh
```

첫 빌드 뒤에는 지문이 앱에 기록되므로 다음 빌드부터는 환경 변수 없이 같은 인증서를 사용합니다. 기존에 고정한 신원과 다르면 의도적인 전환을 위해 `STREAMDOCK_ALLOW_SIGNING_IDENTITY_CHANGE=1`도 필요합니다. 인증서 만료·삭제·변경 시 빌드가 중단될 수 있으며, 다른 신원으로 전환하면 macOS 권한 재허용이 필요할 수 있습니다. 키체인 접근 설정은 변경하지 않습니다.

게임과 화면보호기는 현재 Mac에 설치된 Python과 Pillow를 사용합니다. 이 두 구성 요소를 삭제하거나 옮기면 해당 기능이 동작하지 않을 수 있습니다. Python 자체는 앱에 포함하지 않습니다.

## 기존 설정과 장치

앱은 기존 `~/.config/streamdock-ai` 설정과 `~/.cache/streamdock-ai` 상태를 사용합니다. 빌드는 사용자 설정, Codex·Claude 세션, 훅을 이동하거나 수정하지 않습니다. 이미 설치된 Codex·Claude 훅과 상태 줄은 작업 폴더 안의 스크립트 절대 경로를 참조할 수 있습니다. 이 스크립트가 필요할 동안 기존 작업 폴더를 유지하세요.

네이티브 앱은 자신이 시작한 백엔드만 관리합니다. 시작할 때 127.0.0.1:4174가 이미 사용 중이면 실행 중인 프로세스를 종료하거나 기존 서버에 자동 연결하지 않습니다. 기존 앱을 먼저 종료한 뒤 다시 실행하세요. 공식 StreamDock 앱이 기기를 사용 중인 경우에도 장치 연결이 실패할 수 있습니다. 포트 소유와 임시 토큰을 확인한 뒤 네이티브 설정을 연결합니다.

연결이 끊어지면 백엔드는 재연결을 시도합니다. 시작하거나 다시 연결할 때 휘발성 아이콘 초기화 명령 `CLE`와 화면 갱신 명령을 전송하고, 15개 키와 오른쪽 3개 표시영역을 검은 이미지로 일시 초기화한 다음 현재 화면을 다시 그립니다. 명령 순서와 재연결은 모의 장치로 시험했습니다. 실제 293S에서는 `node-hid`와 Swift HID 각각의 화면·물리 버튼과 USB 분리 후 재연결을 확인했습니다. 2026년 11월 10일 사용자는 이 초기화 순서를 적용한 뒤 키 사이와 오른쪽 표시영역 사이의 부팅 배경이 사라지고 화면과 버튼이 정상이라고 확인했습니다. 검은 초기화 화면 자체나 `CLE` 명령 하나의 효과는 별도로 확인하지 않았습니다. 오른쪽 화면 전체를 하나의 연속된 이미지로 그리는 방법은 아직 확인하지 못했습니다. 기기에 저장된 영구 부팅 로고는 변경하지 않습니다.

앱을 종료하면 자신이 시작한 백엔드에 종료를 요청합니다. 기존 공식 앱이나 다른 프로세스는 종료하지 않습니다. 이 빌드는 로그인 시 자동 실행을 등록하지 않습니다. macOS 접근성·자동화 권한은 사용하는 기능과 앱 서명 상태에 따라 다시 요청될 수 있습니다.

Claude Desktop의 사용량 배지를 대체 수집 경로로 사용하려면 Claude Desktop이 실행 중이고 사용량 배지가 표시되어 있어야 합니다. macOS 접근성 권한도 필요합니다. 수집이 차단되면 앱의 진단 안내에 따라 시스템 설정의 개인정보 보호 및 보안 → 손쉬운 사용을 확인하세요. 2026년 11월 10일 현재 앱을 허용 목록에 다시 추가하고 앱을 재실행한 뒤 Claude Desktop의 7일 사용량이 정상 수집되는 것을 확인했습니다.

Apple Development 서명으로 처음 전환할 때는 이전 임시 서명과 앱 신원이 달라 접근성 권한을 한 번 다시 허용해야 할 수 있습니다. 같은 인증서로 다시 빌드하면 macOS가 같은 앱으로 인식하도록 합니다. 단, 권한 유지 여부는 macOS 상태에 따라 실제로 확인해야 합니다. 허용했는데도 접근성 인증 오류가 계속되면 시스템 설정에서 이전 `StreamDock AI` 항목을 제거하고 현재 `build/native/StreamDockAI.app`을 다시 추가한 뒤 앱을 재실행하세요. 다른 앱의 권한 항목은 변경하지 마세요.

기존 Node 앱으로 돌아갈 때는 먼저 네이티브 앱을 종료합니다. 기존 작업 폴더와 설정을 그대로 사용해 기존 명령으로 실행할 수 있습니다. 293S를 두 앱이 동시에 제어하지 않도록 한 번에 하나만 실행하세요.
