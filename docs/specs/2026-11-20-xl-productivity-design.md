# XL 생산성 기능 묶음 설계

- 작성일: 2026-11-20
- 관련 이슈: #32, #33, #34, #35, #36
- 상태: 구현 중. 장치 동작을 바꾸는 항목은 모두 실물 XL 확인 전에는 merge하지 않는다

## 배경

XL 지원(#17–#31)이 끝나 8×4 배치와 로커가 실물에서 동작한다. 이제 이 장비로 매일 쓰는 도구가 되려면 "에이전트 상태를 보는 것"을 넘어 "한 키로 하는 일"이 필요하다. 이 문서는 어떤 기능을 왜 고르고 무엇을 버렸는지 남긴다.

## 조사

Mirabox 공식 앱(StreamDock·VSD Craft)과 Stream Deck·Companion 커뮤니티, 기존 AI 에이전트 덱 프로젝트(agentsd, VibeDeck)를 살폈다. 반복해서 나오는 쓰임은 다음과 같다.

- 앱 실행·링크 열기·문구 입력·볼륨·음소거 같은 바로가기 키
- 로커·노브로 볼륨이나 목록 넘기기
- 에이전트 "나를 기다리는 중" 신호를 눈에 띄게 하는 상태 키
- 폴더·페이지와 앞 창에 따른 프로필 자동 전환
- 여러 키에 걸쳐 그리는 막대·그래프

LED 프로토콜은 제조사 SDK에 이름(`LBLIG`·`SETLB`·`DELED`)만 있고 바이트 구조는 제3자 역공학 자료뿐이다. 실물 XL에서는 검증되지 않았다.

## 고른 것

| 순서 | 기능 | 이슈 | 이유 |
|---|---|---|---|
| 1 | XL 요약 키를 눌러 이동 | #32 | 이미 화면에 있는 "확인 대기"에서 그 세션으로 한 번에 간다. 코드 변경이 작다 |
| 2 | 바로가기 화면 | #33 | 가장 많이 쓰이는 범주. 프롬프트 문구 키가 에이전트 사용자에게 특히 유용하다 |
| 3 | 로커 볼륨 | #34 | 바로가기의 시스템 동작을 재사용. 기본값은 지금과 같다 |
| 4 | RGB LED 상태 | #35 | 화면을 안 봐도 알린다. 프로토콜이 미검증이라 기본 꺼짐 |
| 5 | 대시보드 | #36 | 8×4에서만 가능한 여러 키에 걸친 표시 |

모든 기능은 설정 파일에서 사용자가 직접 켜거나 정의한다. 에이전트·네트워크 데이터로 명령이나 문구를 만들지 않는다.

## 버린 것 (이유)

- **Claude 권한 요청 승인·거부 키**: 효과는 가장 크다. 하지만 `PermissionRequest` 훅이 덱의 응답을 기다리게 하는 방식이라, 앱이 꺼졌거나 늦으면 실제 Claude 세션이 멈춘다. 다른 방식(터미널에 `y` 입력)은 창 상태에 의존해 부정확하다. 사용자 결정이 필요해 이번에는 하지 않는다.
- **앞 창에 따른 프로필 자동 전환**: 화면이 사용자 모르게 바뀌어 혼란을 줄 수 있고, 백그라운드 감시가 필요하다. 바로가기 화면이 자리 잡은 뒤 다시 본다.
- **멀티 액션 체인·키 조합 보내기**: 크기가 크고 손쉬운 사용 권한을 많이 요구한다.
- **프로젝트별 폴더**: 지금의 프로젝트 → 세션 구조와 겹친다.

## 안전 원칙

- 바로가기·명령은 물리 키(또는 앱 토큰이 있는 API)가 눌렸을 때만 실행한다
- 명령은 셸을 쓰지 않는 절대 경로 + 인자 배열만. 길게 눌러야 실행한다
- 설정 파일은 소유자·심볼릭 링크·크기를 검사해서 읽는다(`market.json`과 같은 방식)
- 권한이 필요한 동작(붙여넣기)은 권한이 없으면 복사만 하고 이유를 알린다
- 실물 확인이 필요한 PR은 열어 두고 확인 절차를 PR 코멘트에 둔다

## 검증

각 PR은 `npm run check`와 모의 장치 테스트까지 한다. 키 위치·화면 모양·LED 색은 사람이 실물에서 확인해야 하고, 결과는 `docs/device-validation.md`에 기록한다.
