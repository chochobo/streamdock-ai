# Stream Dock XL 지원 설계

- 작성일: 2026-11-19
- 관련 이슈: #7 (구현), #6 (조사), #8 (로커 입력, 후속)
- 상태: 구현 완료(#17), 실물 확인 전. 로커 입력은 #18, 키 시험 화면은 #19

## 무엇을 왜

앱은 Stream Dock 293S V3(키 15개 + 오른쪽 표시 전용 3칸)만 지원한다. Stream Dock XL(`5548:1028`, 국제판 `5548:1031`)은 통신 방식이 같고 기기 정의만 다르다(#6 조사 코멘트). XL을 연결하면 32키 전용 배치로 같은 기능을 쓸 수 있게 한다. 293S 동작은 바뀌지 않아야 한다.

| | 293S V3 | XL |
|---|---|---|
| 키 | 15 (3행 × 5열) | 32 (4행 × 8열) |
| 표시 전용 화면 | 슬롯 16·17·18 | 없음 |
| 키 이미지 | 96×96, -90° | 80×80, 180° |
| 보고서 | 입력 512 / 출력 1024, `CRT` 명령 | 같음 |
| 입력 → 위치 | 표 `[13,10,7,…]` | 코드 `0x01` = 왼쪽 위, 오른쪽·아래로 증가 |
| 위치 → 그리기 슬롯 | 같은 표 | 슬롯 1 = 왼쪽 아래, 오른쪽·위로 증가 |

## 핵심 결정

### 1. 기기 정의는 한 곳(`src/device-profiles.mjs`)에 둔다

`PROFILES`의 각 항목이 USB ID·키 수·행열·이미지 크기·회전·표시 전용 슬롯·`slotOf(index)`·`indexOfCode(code)`를 가진다. 드라이버 위의 모든 계층은 **위치(index) = 왼쪽 위부터 행 우선 0-기반 번호**만 쓴다. 슬롯·입력 코드 변환은 드라이버만 한다.

### 2. 배치(layout)는 기기 정의에서 계산한다 — `layoutFor(profile)`

- **제어 키는 마지막 4개**: `modes`(홈) / `usage`·`back`, `prev`, `next`. 293S에서는 11·12·13·14로 지금과 같다. XL에서는 아래 줄 오른쪽 28·29·30·31
- **요약 키**: 표시 전용 화면이 없는 기기는 오른쪽 열의 맨 아래 줄을 뺀 키(XL: 7·15·23)에 지금의 오른쪽 3칸 요약(작업 수·확인 필요·시각)을 그린다. 293S의 오른쪽 띠와 같은 자리 감각을 유지한다. 누르면 아무 동작도 하지 않는다
- **콘텐츠 위치**: 요약 키와 제어 키를 뺀 나머지를 행 우선 순서로 쓴다. 293S 홈 0–10, 페이지 0–11(지금과 같음). XL 홈 25개, 페이지 26개
- **레거시 영역**: 장면·게임(AgentDeck)은 원작이 5×3 + 오른쪽 띠 3칸 그림이라 다시 그리지 않는다. XL에서는 왼쪽 위 5×3 영역(`legacy.keys`)과 그 오른쪽 열 3칸(`legacy.sides`, 5·13·21)에 그대로 그리고 나머지 키는 비운다. 장면 종료 길게 누르기 키(293S 14번)는 XL 20번이 된다

대안으로 검토한 것: (a) XL에 15키 배치를 그대로 옮기기 — 사용자가 32키 전용을 원해 기각. (b) 요약을 키에 두지 않고 앱 창에만 표시 — 기기만 보고 상태를 아는 핵심 용도가 사라져 기각. (c) 장면·게임 원작을 32키로 다시 그리기 — 외부(AgentDeck) 그림 자산 작업이라 범위 밖.

### 3. 연결된 기기가 배치를 정한다

- `createDevice({ profile })`의 `profile`은 시작 기본값이다. 하드웨어 모드에서 `start()`는 **지원하는 모든 기기 정의**의 USB ID로 찾고, 정확히 하나면 그 기기의 정의로 바꾼다. `device.profile()`이 현재 정의를 돌려주고 `status().model`도 그 이름이 된다
- 서버는 새로 고칠 때마다 `device.profile()`을 읽어 배치를 정한다. 정의가 바뀌면 키 캐시를 버리고 다시 계획한다
- 기기가 연결되기 전 기본값은 `STREAMDOCK_MODEL` 환경 변수(`293sv3`·`xl`), 없으면 293S. 이번 실행 중 감지한 기기 정의는 연결이 끊겨도 유지한다(디스크에 저장하지 않음 — 다시 시작하면 잊는다). 시뮬레이터 모드도 `STREAMDOCK_MODEL`을 따른다. Swift 도우미의 `--simulate`는 항상 293S USB ID를 보고한다
- 지원 기기가 두 대 이상 연결되면 열지 않고 실패한다(지금과 같은 "정확히 하나" 규칙). 우선순위 선택은 필요해지면 따로 다룬다
- 서버는 렌더링 직전에 기기 정의가 계획 때와 같은지 확인하고, 다르면 이번 갱신을 건너뛰어 다음 갱신에서 다시 계획한다

### 4. Swift HID 도우미는 기기를 몰라도 되게 한다

이미지 패킷은 Node가 만들고 Swift는 그대로 보낸다(지금과 같음). 바꾸는 것은 셋이다: 지원 기기 목록(USB ID 쌍)으로 찾기, `ready` 이벤트에 `vendorId`·`productId` 싣기, 키 이벤트를 위치(index)가 아니라 **원래 입력 코드**(`code`)로 보내기(`ACK`..`OK` 형식과 `0x01`–`0x26` 범위만 검사). Node의 `createSwiftHID`는 `devicesAsync()`에서 도우미가 알려 준 USB ID를 돌려주고, 코드로 원래 입력 보고서를 다시 만든다. 위치 변환은 `device.mjs` 한 곳에서만 한다.

### 5. 앱(설정 창 미리보기)은 서버가 준 배치를 따른다

`GET /api/status`의 `deck.layout`에 `publicLayout(layout)`(`model, name, cols, rows, keyCount, sideSlots, summaryKeys, controls`)을 싣는다. 앱은 `cols × rows` 격자를 그리고, `sideSlots`가 비어 있으면 오른쪽 띠를 그리지 않는다. XL의 요약 이미지는 `keyFrames`에 요약 키 위치로 들어간다. `layout`이 없으면(이전 백엔드) 293S로 그린다. 화면 문구의 "293S"는 연결된 기기 이름으로 바꾼다.
