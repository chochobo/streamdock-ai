# StreamDock AI

Mirabox StreamDock 293s V3용 macOS 앱입니다. 에이전트와 계정 사용량을 확인하고 게임·타이머·기기 상태 등의 화면을 사용할 수 있습니다. SwiftUI 설정 창과 기기 미리보기를 제공하며, `6603:1014` 장치용 실험적 드라이버를 포함합니다.

## macOS 앱

```sh
./scripts/native-build.sh
open build/native/StreamDockAI.app
```

앱의 설정 창은 SwiftUI로 구현했습니다. 장치 연결은 Swift HID가 기본이며, 기능은 앱에 포함한 Node 백엔드가 담당합니다. 게임과 장면에는 이 Mac의 Python·Pillow가 필요합니다. 완전한 Swift 전환은 아직 진행 중입니다. 빌드 조건, 기존 설정·훅 보존과 `node-hid` 복구 방법은 [macOS 앱 안내](docs/native-macos.md)를 참고하세요. 앱이 실행 중이면 먼저 종료한 뒤 다시 빌드하세요.

## 백엔드 개발 실행

Node.js 22 이상이 필요합니다. 게임과 장면에는 Python 3와 Pillow도 필요합니다. 현재 Python 환경에서 `python3 -c "import PIL; print(PIL.__version__)"`으로 확인할 수 있습니다.

아래 첫 줄의 경로를 프로젝트를 내려받은 위치로 바꾸세요.

```sh
cd /path/to/streamdock-ai
npm install
npm start
```

기본 실행은 모의 장치 모드입니다. 실제 장치에는 쓰지 않습니다. 종료하려면 터미널에서 `Ctrl+C`를 누르세요. 기기 화면과 설정은 위의 macOS 앱에서 확인할 수 있습니다. 같은 포트나 기기를 사용하려면 독립 실행한 백엔드를 먼저 종료하세요.

## 293s V3에 표시하기

**실험 단계입니다.** 연결된 장치는 제조사 SDK에서 293s V3로 식별하는 `6603:1014`입니다. 2026년 11월 9일 실물 시험에서 사용자가 시험 화면 15개가 모두 바른 방향으로 표시된 것을 확인했습니다. 왼쪽 위와 오른쪽 아래 버튼을 눌렀을 때 앱은 각각 1번과 15번 입력을 받았습니다. 사용자는 실제 대시보드 모드에서 에이전트 상태 화면이 표시된 것도 확인했습니다. 이 모드에서 8번 키를 눌렀을 때 앱은 입력과 상태 갱신을 기록했습니다. 나머지 키의 입력은 아직 실물에서 확인하지 않았습니다.

1. 공식 StreamDock 앱을 종료하세요. 두 프로그램이 장치를 동시에 제어하지 않도록 이 앱은 공식 앱이 실행 중이면 장치를 열지 않습니다.
2. 별도로 실행 중인 StreamDock AI 백엔드가 있으면 종료합니다.
3. 위의 macOS 앱을 실행하고 `기기` 또는 `연결과 진단`에서 연결 상태를 확인합니다.
4. 첫 화면에서 프로젝트를 누르면 해당 프로젝트의 Codex·Claude Code 세션을 볼 수 있습니다. 세션을 누르면 연결된 채팅이나 터미널을 열도록 요청합니다. 첫 화면의 아래 줄은 프로젝트 한 칸, `기능`, `사용량`, `이전`, `다음` 순서입니다. 상태는 2초마다 수집하고 바뀐 키만 다시 전송합니다. 이동 방식과 제한은 [세션 열기 안내](docs/focus.md)를 확인하세요.

오른쪽 화면은 표시 전용 영역 3개로 구성합니다. 작업 중·확인 필요·완료 수, 감지된 확인 필요 항목과 마지막 갱신 시각을 표시합니다. 추정 상태는 `?`로 구분합니다. 상태는 2초마다, 시각은 1분마다 확인하며 바뀐 영역만 전송합니다. 2026년 11월 9일 사용자가 실제 장치에서 오른쪽 요약 화면이 표시되는 것을 확인했습니다. 번호를 붙인 시험 화면으로 16·17·18 영역의 순서를 눈으로 확인하지는 못했습니다. 이후 사용자가 제공한 사진에서 오른쪽 화면의 왼쪽 글자가 잘린 것을 확인했습니다. 사진을 바탕으로 글자를 안쪽에 배치했습니다. 사용자는 보정 후 작업·확인·완료와 갱신 시각이 잘리지 않고 보이는 것을 확인했습니다. 정확한 물리적 표시 범위는 측정하지 않았습니다.

앱을 종료하면 장치를 놓습니다. 다시 공식 앱을 사용할 수 있습니다. 연결이 끊어지면 앱은 자동 재연결을 시도하고, 다시 연결되면 현재 화면을 다시 보냅니다. 기기 시작·재연결 시 휘발성 아이콘 초기화 명령 `CLE`와 화면 갱신 명령을 보낸 뒤, 15개 키와 오른쪽 3개 표시영역에 검은 이미지를 보내고 현재 화면을 그립니다. 이 과정은 기기에 저장된 영구 부팅 로고를 변경하지 않습니다. 2026년 11월 10일 사용자는 이 초기화 순서를 적용한 실제 293S에서 키 사이와 오른쪽 표시영역 사이의 부팅 배경이 사라지고 화면과 버튼이 정상이라고 확인했습니다. 이 결과만으로 `CLE` 명령 하나의 효과를 분리해 확인한 것은 아닙니다. 오른쪽 화면 전체를 하나의 연속된 이미지로 그리는 방법은 아직 확인하지 못했습니다.

`CLE`를 포함한 시작 초기화와 18개 표시영역은 모의 장치로 시험했습니다. 2026년 11월 10일 실제 293S에서 `node-hid`와 Swift HID 각각의 화면·물리 버튼과 USB 분리 후 자동 재연결을 확인했습니다. 검은 초기화 화면 자체는 실제 기기에서 별도로 확인하지 않았습니다. 네이티브 앱은 Swift HID를 기본으로 사용하며 `--node-hid` 실행 옵션으로 이전 드라이버를 선택할 수 있습니다. 장치가 연결되지 않으면 USB 연결, 공식 앱 실행 여부와 macOS 권한을 확인하세요. 다른 모델과 USB ID는 지원하지 않습니다.

## 기능 화면

프로젝트 화면의 아래 줄 두 번째 `기능`을 누르면 기능 목록이 열립니다. 요약, 에이전트, 기록, 사용량, 머신, 타이머, 주식, 게임, 장면, 워크트리, 택배, 크레딧, 원격과 설정 화면을 선택할 수 있습니다. `이전`, `다음`, `뒤로`로 이동합니다. 기능별 설정과 사용 조건은 [기능 안내](docs/features.md)에 있습니다.

게임은 두더지, 기억 게임, 짝 맞추기, 슬롯, 블랙잭, 포커, 레이스를 제공합니다. 장면은 수족관·벽난로·비·해변입니다. 장면을 끝내려면 실제 기기의 맨 아래 오른쪽 키를 1.2초 이상 누릅니다. 효과음과 자동 화면보호기는 기본적으로 꺼져 있습니다. 기기 설정에서 켤 수 있습니다.

택배, 원격 조회와 일부 크레딧은 별도 설정이 필요합니다. 정리·휴지통·워크트리 삭제는 미리보기만 제공하며 실행은 차단돼 있습니다. 업데이트는 신뢰할 저장소 설정 후 원격 상태를 확인할 수 있지만 앱에서 자동 적용하지 않습니다. 새 기능의 전체 화면과 버튼은 아직 실제 293S에서 모두 검증하지 않았습니다.

## 계정 사용량

Mac 앱의 **에이전트와 사용량** 화면에서 Codex와 Claude Code의 사용률과 리셋 시각을 확인합니다. 293S에서는 프로젝트 화면의 맨 아래 줄 세 번째 **사용량** 키를 누릅니다. 제공된 각 사용 구간의 사용률과 리셋 시각은 두 키로 표시하며, **뒤로**로 프로젝트 화면에 돌아갑니다. 제공되지 않은 구간은 표시하지 않으며, 그 사실만으로 요금제의 한도를 확정하지 않습니다. 계정 전체를 확인할 수 없으면 미확인 키 하나를 표시합니다.

Codex는 로컬 CLI의 인증 계정에서 공식 app-server로 확인합니다. Claude Code는 status line이 전달한 값을 읽고, 해당 값이 없으면 실행 중인 Claude Desktop 사용량 배지의 접근성 텍스트를 대체 경로로 읽습니다. Desktop 경로에는 macOS 접근성 권한과 보이는 사용량 배지가 필요하며, 계정은 `계정 미확인`으로 표시합니다. 실제 기기에서 주간 사용률과 리셋 문구가 Claude 화면과 일치하는 것을 확인했습니다. 요일·시각만 제공된 경우 날짜는 추정하지 않습니다. 값이 없거나 오래되면 그 상태를 표시합니다. 갱신 방식과 설정 복원은 [사용량 안내](docs/usage.md)를 확인하세요.

## 에이전트 상태

- 첫 화면에는 열려 있다고 확인된 상위 세션의 프로젝트를 우선 표시합니다. `기능` → `기록`에서 확인되지 않은 세션과 이전 기록을 볼 수 있습니다. 열린 상태는 작업 중을 뜻하지 않습니다.
- Codex: 로컬 세션 기록과 선택형 상태 훅의 관측값을 사용합니다. 정확한 상태를 확인할 수 없는 경우 `미확인`으로 표시하며, 추정에는 `?`를 붙입니다. 훅의 신뢰 검토와 제한은 [Codex 훅 안내](docs/codex-hooks.md)를 확인하세요.
- Claude Code: 상태 훅을 설치하면 작업, 승인 요청, 완료와 종료 이벤트를 관측합니다. 모든 Desktop 세션의 정확한 상태를 보장하지는 않습니다. 설치 여부 확인과 설정 방법은 [훅 설정과 해제 안내](docs/hooks.md)를 참고하세요.
- 기존 AgentDeck 훅 기록도 읽습니다. 관측이 오래됐거나 근거가 부족한 상태는 `미확인`이며, 종료를 뜻하지 않습니다.

앱은 Codex와 Claude의 로컬 세션 기록에서 상태 이벤트와 메타데이터를 읽습니다. 세션을 식별하기 위해 로컬 상태 파일에 원본 세션 ID와 절대 작업 경로, 선택적으로 프로세스 ID·시작 시각·TTY·앱 식별자가 저장됩니다. 새 상태 파일은 소유자만 읽고 쓸 수 있는 `0600` 권한으로 만듭니다. 이 값들은 상태 API에 반환하지 않습니다. 세션 제목에는 작업 내용이 들어갈 수 있으며 화면과 상태 API에 표시되므로 공유 화면에 유의하세요. 서버는 `127.0.0.1`에서만 요청을 받습니다.

## 테스트

```sh
npm test
```

자동 드라이버 테스트는 모의 HID 장치를 사용합니다. 실제 293s V3에서는 위에 적은 시험 화면과 에이전트 상태 화면, 1번·8번·15번 버튼 입력을 확인했습니다. 2026년 11월 9일 사용자가 실제 기기의 프로젝트·세션 화면과 현재 Codex 채팅 및 활성 Claude 세션 이동을 확인했습니다. 이후 현재 계정 필터를 적용하고 버튼과 같은 앱 API를 사용해 다른 Claude 채팅에서 선택한 기존 채팅으로 전환되는 것도 확인했습니다. 이 시험은 선택한 세션에 한정되며 모든 계정과 세션의 이동을 보장하지 않습니다. 딥링크 요청 수락과 실제 채팅 선택은 다릅니다. 제한은 [세션 열기 안내](docs/focus.md)를 참고하세요.
